# RC-Tags (unabhängig von den Kriterien)

Der stündliche RC-Workflow verwendet `tag-delta` zur Generierung freier Suchbegriffe. `retag` ist nur manuell und berücksichtigt die Version aus Prompt, Modell und Tag-Limit. `tag-refresh` veröffentlicht ohne KI. Vorhandene Klassifizierungen bleiben erhalten. Die Prompt-Regeln stammen aus `Config.gemini_prompt` (B7), die Obergrenze aus `max_additional_tags`; optional ist `tag_model` konfigurierbar. Die Responses API gibt nur ein JSON-Array `tags` zurück, keine Begründungen. Die Tags werden pro Veranstaltung getrennt als `tagging.tags`, `tagging.revision` und `tagging.content_hash` in `rc-data` gespeichert und als Such-Chips auf `/rc/` angezeigt.

Die alten Ausgaberegeln in B7 für `standard_tags` und `reason` werden technisch übersteuert. Die aktuelle Version verändert keinen Kriterien-Fingerprint. Das stündliche Tagging ist ein kostenpflichtiger API-Aufruf nur für neue bzw. geänderte Veranstaltungen. Fehler überschreiben keine vorherigen Tags. Vor produktivem Merge sind ein Live-Lauf, Checkpoint-Veröffentlichung und UI-Suche zu validieren.
